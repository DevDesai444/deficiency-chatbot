<objective>
Ship the enforcement layer: the "zero true-positives-lost" code gate (EVAL-03), a single CI-style
command that scores a run and applies the gate, and a committed baseline recording the measured
7%-recall-by-family starting point. This is where the harness becomes the continuous gate on every
later phase — enforced in code, not a prompt or a convention (PITFALLS.md #4).

Purpose: A filter can only ever REMOVE findings; the gate makes a lost true positive fail the build
loudly. The baseline freezes the starting line so "no phase improves unless recall-by-family moves
without losing a TP" becomes a mechanical check.
Output: `src/evals/gate.py`, `src/evals/run.py` (CLI), `src/evals/baseline/recall_by_family.json`,
`docs/eval/BASELINE.md`, and CI tests.
</objective>

    - The two tp_required anchors (C-01, C-02) are always in the protected baseline found-set.
