<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Reference extraction from untrusted docs | hyperlinks in DOCX rels, link annotations in PDF, regex over canonical text |
| edges.py SQLite write from reference extractor | Edge records written by the reference extractor; later read by follow_reference |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05W2B-01 | Tampering | Malicious hyperlink target URI in DOCX rels | mitigate | reference extractor stores the target URI as a string in the edge record but NEVER resolves/fetches it (no network call). The URI is treated as an opaque identifier for anomaly detection. No SSRF risk. |
| T-05W2B-02 | Tampering | Regex injection via crafted canonical text | mitigate | _REF_PATTERNS use re.compile with fixed patterns; they are not constructed from user input. The canonical text is an input to re.finditer, not to re.compile. No injection risk. |
| T-05W2B-03 | Tampering | Forged edge provenance in SQLite (tampered edges.db) | mitigate | edges.db is under ingest.limits.safe_resolve protection (corpus root). The provenance_span_id is validated at emit_reference_finding call time via open_span HashMismatch check. A forged edge would fail the hash check. |
| T-05W2B-04 | Denial of Service | Corpus with 100k cross-reference patterns (runaway regex) | mitigate | Apply a cap on the total number of edges extracted per doc (e.g., 1000); log a warning when cap is hit. The _REF_PATTERNS are simple, non-backtracking regexes with no catastrophic complexity. |
</threat_model>
