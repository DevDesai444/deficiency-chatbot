<objective>
Define the coverage-manifest schema (INGEST-03, D-30/D-16/D-17/D-18) and the content-hash-keyed persistence store (D-14/D-15/D-32): a resumable, version-invalidated per-document cache that retains the full canonical text, plus an SQLite corpus index following the existing job-store conventions.

Purpose: SC3 — "after ingestion, the system exposes a per-submission corpus index and coverage manifest listing every document, its content-derived classification, title, and section outline." SC6 — "ingestion declares a per-document availability contract so downstream phases read capability from the manifest instead of discovering it at runtime." D-32 leaves the full canonical text on disk so Phase 2 `get_section` and Phase 4 reference extraction don't re-parse the corpus.
Output: `ingest/manifest.py`, `ingest/store.py`.

**Storage-format decision (D-15, Claude's discretion — documented):** the corpus index metadata + manifest use **SQLite** following `src/databricks/delta.py` conventions (conn + `row_factory=sqlite3.Row` + JSON columns), the existing job store. The per-document parse cache (which retains the full canonical text, D-32) is written as one JSON file per content-hash under a controlled cache dir, atomically (temp→rename). Rationale: SQLite matches the established job store (D-15); a JSON-per-doc cache keyed by content-hash is trivially resumable and never writes under an attacker-controlled filename.
</objective>

<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| cache writer → filesystem | Cache files are keyed by content-hash under a controlled cache dir; the store never writes under an attacker-controlled filename. |
| corpus scale → memory | At 500-doc scale the store persists per-file and streams; parsed docs are not all held in memory. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Elevation / Info Disclosure | cache path derived from attacker filename | mitigate | Cache keyed by content-hash under a fixed cache dir; never the source filename/path. |
| T-01-08 | DoS | resource exhaustion at 500-doc scale | mitigate | Per-file on-disk cache + atomic write; the corpus (Plan 09) streams and degrades to `parse_failed` rows rather than OOM. |
| T-01-10 | Tampering | stale/drifted cache served after a normalizer change | mitigate | Cache key includes `normalizer_version`+`serializer_version`; a bump invalidates (Pitfall 6, D-24). |
</threat_model>
