<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| filesystem (untrusted PDF/DOCX) → parser | Every submission file is hostile until size/entry/path/time-capped. `limits.py` is the choke point crossed before any heavy parse. |
| serializer → offset space | Raw serialized offsets are internal; span identity is minted later over the CANONICAL stream (Plan 06). No geometry enters identity (D-19). |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Denial of Service | DOCX zip / decompression bomb | mitigate | `docx_zip_guard`: cap uncompressed size + entry count + compression ratio before `docx.Document()` (Plan 04 calls it). |
| T-01-02 | DoS / Tampering | malformed/adversarial file | mitigate | `check_file_limits` byte ceiling + `PARSE_TIMEOUT_S`/`MAX_PAGES` consumed by the parsers; per-file try/except never-abort lives in Plan 09. |
| T-01-03 | Elevation / Info Disclosure | path traversal / symlink escape | mitigate | `safe_resolve` refuses `..`/absolute/symlink escapes out of corpus root; cache keyed by content-hash not filename (Plan 07). |
| T-01-06 | Path traversal | zip-slip in DOCX part names | mitigate | `docx_zip_guard` rejects entries containing `..` or absolute paths. |
</threat_model>
