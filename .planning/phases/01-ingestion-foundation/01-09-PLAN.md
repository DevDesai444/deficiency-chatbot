<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| filesystem tree (untrusted, arbitrary depth) → corpus walk | The whole directory is untrusted: file count, nesting, names, symlinks, and file contents are all adversary-controlled. The walk is the outermost trust boundary of the system. |
| per-file parse → batch | One malicious/malformed file must not compromise the batch; each file is isolated and degraded to a manifest row. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02 | DoS / Tampering | malformed/adversarial PDF/DOCX in the tree | mitigate | `limits` caps before parse + per-file try/except → `parse_failed` row; the 500-doc batch never aborts (D-16). |
| T-01-03 | Elevation / Info Disclosure | symlink/`..` escape during the walk | mitigate | `limits.safe_resolve(root, path)` refuses escapes; cache keyed by content-hash not filename. |
| T-01-01 | DoS | DOCX zip bomb | mitigate | `limits.docx_zip_guard` invoked before `extract_docx`. |
| T-01-04 | Tampering | folder-name-driven misclassification | mitigate | Path never passed to `classify_document`; SC1 rename-folders test proves invariance (D-09). |
| T-01-08 | DoS | resource exhaustion at 500-doc scale | mitigate | Streaming per-file + on-disk resumable cache (Plan 07); degrade to rows, not OOM. |
| T-01-17 | Tampering | scanned-table loss passed off as complete evidence | mitigate | Flat-text OCR / lost tables → `parsed_partial` + `tables:unavailable` (D-17/D-30), so a lost table is visibly ineligible for X1, never a silent false negative. |
</threat_model>
