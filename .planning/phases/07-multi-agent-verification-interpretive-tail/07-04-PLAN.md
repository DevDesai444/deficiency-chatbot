<objective>
Wave 3: add the precision-gated interpretive tail, the single report-assembly DRIVER seam, and wire
the phase gate. The tail reuses the existing Phase-3 hand-rolled review loop on a Qwen producer to
surface grounded deficiencies no deterministic rule expresses; each is emitted through the byte-exact
emit_finding grounding gate, tagged with its producer family, and passed through the SAME consensus
verifier. The driver combines Phase-5 candidates + tail candidates through the ONE verify_candidates
fan-out and assembles the scored FaultReport (KEEP-tier only) + CoverageReport (Gap 2). Finally, a
verify-f1 gate — driving THAT driver — proves verification + tail does not lower end-to-end F1 and
loses zero true positives vs. the frozen Phase-5 baseline, and hard-fails an authored-* baseline on a
real run (Gap 3).

Purpose: VERIFY-04 (interpretive tail) + the driver seam (Gap 2) + the phase gate that grades the
whole phase (Gap 1 surfacing + Gap 3 falsifiability). The P3 NO-GO is the governing caution — the
tail is tightly budgeted, hard precision-gated, and disabled for a run if it adds FPs the consensus
verifier does not catch.

Output: src/verify/{tail,driver}.py + a verify-f1 gate subcommand in evals/run.py + three tests
(test_tail_gate, test_verify_driver, test_verify_f1_gate) green. Includes a human-verify checkpoint
for the MAIN-tree live F1 measurement + baseline re-capture (gitignored corpus).
