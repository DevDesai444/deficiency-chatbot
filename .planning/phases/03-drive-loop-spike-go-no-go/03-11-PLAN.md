<objective>
Build the layer between the model and the tools: seven pydantic arg models, the schemas derived from them, dispatch, and the two-layer repair accounting.

**D-LOOP3** makes the arg model the single source of truth — the schema the model is *shown* and the model that *validates its reply* cannot drift apart, because they are the same object.

**The Databricks constraint that shapes every model.** The vendor prohibits `anyOf`/`oneOf`/`allOf`/`prefixItems`/`$ref` in tool schemas, caps JSON-schema keys at 16 and tools at 32, and states *"Parallel function calling is not supported."* A pydantic arg model declaring `submission_span_id: SpanID` emits `{"$ref": "#/$defs/SpanID"}` plus a `$defs` block, and `structured.py::_sanitize` **preserves `$defs` by design** (`:37`). So **span-IDs must cross the boundary as flat strings** — which is also what D-GRAN already requires, since `[doc:start:end]` is the only form any tool renders and the model must select an ID it can see rather than compute an offset.

**Pitfall 6 shapes the optional parameters.** A documented Qwen failure: *"It repeatedly calls the same tool; the call is almost correct, but one optional parameter is missing… when I changed the `offset` parameter from optional to required, the problem disappeared entirely"*, with onset around 30k tokens. `get_section` has **four** optional params and `read_guideline` has **three**. Worse, this failure presents as D-BUD3's identical-args breaker and as a D-TEL4 malformed rate — it would be **diagnosed as model incompetence when it is a fixable schema shape.** D-RI2 locks the single-optional-`citation` enumerate-vs-fetch surface as *"exactly"* what Phase 3 tests, so the lock is honored — and a named, bounded fallback is pre-registered instead of improvised mid-run.

Purpose: AGENT-01's tool loop cannot issue a single call until these schemas are legal and these args validate.
Output: `ToolRegistry` with all 7 tools, the schema-restriction test suite, and the pre/post-repair split D-TEL4 reads.
</objective>

```python
def render_rejection(r: ToolRejected) -> str:
    """D-LOOP5: rejections invisible to the model make the emit gate a WALL instead of a TEACHER.
    Every hint in src/tools/ names the NEXT CALL TO MAKE ("call open_doc first",
    "re-fetch via read_guideline, then cite the span-ID it returns"). Dropping hint/preview/handle
    would leave the agent re-emitting the same fabricated quote with no idea why nothing lands."""
    parts = [f"REJECTED[{r.reason_code}] {r.reason}"]
    if r.hint:    parts.append(f"HINT: {r.hint}")
    if r.preview: parts.append(r.preview)      # TOOLS-04 oversized path carries real span-IDs
    if r.handle:  parts.append(f"handle={r.handle}")
    return "\n".join(parts)
```

`preview` matters specifically: on a `range_too_large` rejection it carries real, citable span-IDs, so dropping it would turn a recoverable oversize into a dead end.

**(d) Result rendering.** Tool results go back to the model as strings. `search_corpus` returns a list of dicts whose `snippet` already carries `[doc:start:end]` annotations — render them so those IDs survive verbatim. **Never truncate an oversized result**: Claude Code's own A/B found truncating over-cap reads *"dropped tool error rate but raised mean tokens"* and reverted it; an error tool-result is ~100 bytes versus ~25k for a truncated one. `tools/oversized.py`'s persist/preview/handle path already handles this — use it, do not add truncation.

**(e) Never author evidence.** Nothing in the registry may accept free-text evidence from the model. A `Fault`'s `evidence` comes from `open_span` inside `emit_finding` (`:82,112-116`). This is the strongest security property the design has and must not be weakened.
