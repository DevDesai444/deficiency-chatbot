<objective>
Build the loop itself — the thing AGENT-01 claims exists. The model requests evidence, reasons over it, requests more, and stops. Everything about *when* it stops lives in plan 03-14; this plan builds the turn machinery, the static prefix, and the message protocol.

**D-LOOP4 is paid here and it is nearly free now.** COST-01's cache-stability invariant says the system prompt and tool schemas stay **fully static**; corpus manifest, document counts, detected families and any rule enumeration go **in messages**. Ship the cross-corpus byte-identical-prefix test with the loop rather than waiting for Phase 6, because retrofitting means re-threading every dynamic value out of the prefix after three phases of code depend on it. Claude Code measured a dynamic tool description busting the schema cache at *"~10.2% of fleet cache-creation tokens"*; Phase 6's SC1c warns that getting this wrong *"silently forfeits the entire caching lever."*

**Pitfall 10 is the other half.** OpenAI-compatible tool protocols require the assistant message carrying `tool_calls` to be echoed back **verbatim**, with each result appended as `{"role":"tool","tool_call_id": <id>,"content": <str>}`. Hand-reconstructing that message — dropping `tool_calls`, mismatching an id — produces 400s or silent context loss on turn 2. `ChatTurn.raw_message` exists for exactly this.

Purpose: this is the file the gate's number is produced by.
Output: a static prompt module, `run_review`, and three offline tests proving the loop turns, the protocol holds, and the prefix is stable.
</objective>

The loop **never imports** `chat_completion_tools`. `RetrievalLedger`'s own header is the precedent: *"Constructor-injected, never a module global (Security Domain V3): one instance per agent run, threaded explicitly through every tool call."*

**The prefix rule** (D-LOOP4):

```python
# src/agents/review/prompts.py
SYSTEM_PROMPT = """..."""          # module constant -- no f-string, no .format(), no corpus data

# src/agents/review/loop.py
def build_messages(corpus_brief: str) -> list[dict]:
    return [
        {"role": "system", "content": SYSTEM_PROMPT},        # STATIC PREFIX
        {"role": "user",   "content": corpus_brief},         # manifest/doc-count/families HERE
    ]
```

**The analog to copy structurally and invert.** `src/agents/detection/prompts.py` uses module-level triple-quoted constants — copy that shape. But it fills `{}` placeholders via `.format()` at four call sites, and **D-LOOP4 forbids exactly that** for the system prompt.

`llm.client.ChatTurn` (plan 03-03): `content`, `finish_reason`, `tool_calls`, `raw_message`, `prompt_tokens`, `completion_tokens`, `cached_tokens`, `usage_present`. `raw_message` is `choice.message.model_dump()` and must be appended unmodified.

`ToolRegistry` (plan 03-11): `schemas() -> list[dict]` in fixed order, `dispatch(name, raw_args) -> DispatchResult` carrying `result`, `turn_consumed`, `repair_layer`, and the breaker key; plus `render_rejection(r)`.

`BudgetLedger` (plan 03-07): `record_turn`, `record_productivity`, `record_tool_call`, `record_rejection`, `over_ceiling`, `over_wall_clock`, `over_turns`, `in_diminishing_returns`, `breaker_tripped`, `may_nudge`, `stop_reason`.

`TurnLog` (plan 03-08): `turn(**fields)`, `continuation(...)`, `rejection(...)`, `repair(...)`, `oracle_leads(...)`.

**`follow_reference` is an honest boundary, not a failure.** It returns `{"status": "cross_document_resolution_pending_phase_4"}` for anything it cannot resolve same-document (`follow_reference.py:18,27,38`). The loop must treat it as a declared capability boundary and **must not retry it** (D-30).

**Databricks:** *"Parallel function calling is not supported."* Iterate `tool_calls` defensively as a list, but never depend on more than one per turn.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| System prompt to provider cache | A dynamic byte in the prefix silently forfeits prompt caching for every run |
| Message history to provider | Malformed tool-call pairing produces 400s or silent context loss |
| Model self-assessment to termination | The model's "I'm done" must not be a termination condition |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
