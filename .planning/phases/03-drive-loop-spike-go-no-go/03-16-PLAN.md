<objective>
Set the budget ceilings honestly, and stop for the reviewer on the one question this planner is not allowed to answer.

**D-BUD1's order is the whole point.** Declare the multiple **first**, then calibrate, then freeze. *"Chosen and written BEFORE calibration runs so the number cannot be tuned to a result."* And calibration executes on a **held-out corpus, never the scored eval set** — measuring consumption on the same documents the gate scores would mean seeing agent findings on scored data before freezing the criteria, *"the exact post-hoc contamination the pre-registration exists to prevent, arriving through the back door."* Nothing is lost by calibrating elsewhere, because **consumption generalizes across corpora; findings do not.**

**FLAGGED, NOT RESOLVED — the held-out corpus is inadequate.** CONTEXT.md names `spec32s41` as the default choice and instructs: *"If the planner finds it insufficient for a full multi-document consumption measurement (D-BUD5's corollary), FLAG it rather than substituting scored data."*

It is insufficient. `spec32s41` is the **only** genuinely held-out real submission document, it is **one PDF**, and it carries 3 GT deficiencies. Everything else in the repo is either scored (`mvr1381`, `minispec`), a byte-duplicate of a scored PDF (`Sample Data/*.pdf`), or a 1,425-byte toy fixture (`data/test_spec.pdf`). D-BUD5's corollary requires a **full multi-document review**, because a per-run budget's whole purpose is measuring how an agent *allocates across documents* — and a single document cannot exercise that. Freezing a 3x ceiling on it risks discovering D-BUD1(c)'s "infeasible multiple" scenario *during run 1*.

So this plan **stops for the senior reviewer** with three non-contaminating options and picks none of them.

Purpose: the frozen ceilings go into the committed pre-registration and cannot be amended once a run begins.
Output: pre-declared multiples, a reviewer-chosen corpus, a measured multi-document consumption figure, and frozen ceilings.
