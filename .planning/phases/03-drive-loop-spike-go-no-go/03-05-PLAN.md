**(a) `ScriptedChatClient`** — replays a fixed turn list and records what it was asked, so message-history construction is assertable:

```python
@dataclass
class ScriptedChatClient:
    """Deterministic stand-in for llm.client.chat_completion_tools (RESEARCH.md Pattern 1).

    The loop receives a completion CALLABLE rather than importing the client, so every offline
    test here needs zero monkeypatching of module globals -- the same discipline ledger.py:3-5
    already documents for RetrievalLedger. `seen_messages` / `seen_tools` are deep copies, so a
    test can assert exactly what the loop sent on turn N even after the loop mutates its list.
    """

    script: list[ChatTurn]
    seen_messages: list[list[dict]] = field(default_factory=list)
    seen_tools: list[list[dict]] = field(default_factory=list)

    def __call__(self, messages, tools, **kw) -> ChatTurn:
        self.seen_messages.append(copy.deepcopy(messages))
        self.seen_tools.append(copy.deepcopy(tools))
        return self.script[min(len(self.seen_messages) - 1, len(self.script) - 1)]
```

The clamp on the last script entry matters: a budget test needs the client to keep answering after the script runs out, so the *loop's* stop condition is what ends the run rather than an `IndexError`.

**(b) `ForcedRunaway`** — never emits a stop, always requests more evidence, cycling **real** tool calls so the real `src/tools` functions execute against a real offline `CorpusIndex` (D-BUD6):

```python
@dataclass
class ForcedRunaway:
    """D-BUD6's synthetic driver. Never stops; always requests more evidence. Deterministic,
    offline, CI-runnable under D-RB6, zero LLM spend -- and it exercises exactly what SC3 claims
    (ceiling trips, grounded partial returned, no crash, no overspend). A code gate deserves a
    test that cannot be flaky for model reasons."""

    prompt_tokens: int = 4000
    completion_tokens: int = 200
    i: int = 0

    def __call__(self, messages, tools, **kw) -> ChatTurn:
        self.i += 1
        return ChatTurn(
            content="", finish_reason="tool_calls",
            tool_calls=[make_tool_call("search_corpus", {"query": f"impurity {self.i}"})],
            raw_message={"role": "assistant", "content": None, "tool_calls": [...]},
            prompt_tokens=self.prompt_tokens, completion_tokens=self.completion_tokens,
            usage_present=True,
        )
```

The query varies per call so the circuit breaker's identical-args condition does NOT trip — the token ceiling must be what ends a D-BUD6 run, otherwise the test proves the wrong gate.

**(c) `ReplayClient`** — replays a committed real-run transcript (a JSONL of turns) so a real model's actual call sequence can be regression-tested offline without spend. It reads a fixture path and yields `ChatTurn`s in order; on exhaustion it returns a no-tool-call turn so the loop terminates naturally.

**(d) A `make_tool_call(name, args) -> object` helper** producing an object shaped like `openai`'s `ChatCompletionMessageToolCall` — it needs `.id`, `.function.name`, `.function.arguments` (a JSON **string**, not a dict, because that is what the real SDK delivers and the registry must parse). Give each call a unique deterministic id (e.g. `call_{n:03d}`) so `tool_call_id` pairing is assertable.

**(e) `build_multi_corpus_index(tmp_path, docs) -> CorpusIndex`** — extend `build_corpus_index` to N documents. `docs` is a list of `(doc_id, blocks, outline_headings)` tuples. It MUST persist every document through the same real `serialize_document -> normalize -> build_table_index -> write_doc_cache` path and return one `CorpusIndex` whose manifest lists all N, so `cached_entry(doc_id)` returns a genuine entry for each. Import and reuse `tests.tools.conftest.build_corpus_index`'s internals rather than duplicating them; never hand-roll a cache dict.

This is the fixture D-BUD5 depends on: a per-run budget's whole purpose is measuring how an agent *allocates across documents*, and a single-document corpus cannot exercise that.

Also add a `budget_ledger` / `retrieval_ledger` pytest fixture pair that constructs **fresh instances per test** — never module-level singletons (Security Domain V3).
