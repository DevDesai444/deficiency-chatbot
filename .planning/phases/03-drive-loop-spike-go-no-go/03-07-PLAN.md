<objective>
Build the object that makes AGENT-03 and AGENT-04 true. Both requirements are satisfied **by code the model cannot talk its way past** — a plan whose acceptance amounts to "the system prompt tells the model to stop" is wrong by construction. `BudgetLedger` is where every stop condition lives as a method.

Six conditions, each a locked decision:
- **Token / wall-clock / turn ceilings** (AGENT-03, D-BUD5) — per-run, counting input plus output across every turn **including tool results**, wall-clock including tool execution time. Per-run and not per-document because a per-document budget lets an agent exhaust itself on document 1 and skim the rest, *"reproducing the 2/28 ceiling by a different route while each document individually looked well-behaved."*
- **Diminishing returns** (AGENT-03, D-BUD2) — N consecutive unproductive turns halt the loop *before* the ceiling, so budget buys progress rather than circling.
- **Circuit breaker** (D-BUD3) — identical `(tool, args)` N times, or N consecutive rejections sharing the same `(reason_code, half)`. The second condition catches the real pathology: a model that varies its args slightly while making the same class of mistake.
- **Continuation floor** (AGENT-04, D-BUD4) — DR-bounded OR a hard max, ORed, whichever fires first, recording which bound ended it.

Purpose: this is the deliverable the gate measures. Owning the loop means owning exactly this code.
Output: `BudgetLedger` with every condition as a pure, unit-testable method, and a test file that proves each one in isolation before any loop wiring exists.
</objective>

**The N values, decided and frozen here. Every one lands in the committed pre-registration (plan 03-17, D-GO5):**

| Parameter | Value | Rationale |
|---|---|---|
| `breaker_repeat` (identical `(tool, args)`) | **3** | Claude Code's own budget logic uses `continuationCount >= 3` as its repetition threshold. Three byte-identical calls is unambiguous circling with no innocent reading. |
| `breaker_same_class` (consecutive same `(reason_code, half)`) | **4** | Deliberately more permissive than the identical-args rule: D-LOOP5 makes a rejection a teaching turn with a `hint`, so the model deserves 2-3 genuine self-correction attempts. Four consecutive same-class failures means the hint is not landing. |
| `dr_window` (consecutive unproductive turns) | **3** | Matches the Claude Code precedent. **2 is unsafe** even with the Pitfall-4 amendment: a legitimate sequence is enumerate, enumerate(different family), search-returning-known-spans. |
| `max_continuations` (D-BUD4 hard cap) | **5** | D-TEL5's own wording is *"nudged 4 of a permitted 5"*. Gives headroom over the DR bound (3) so the two bounds are genuinely distinguishable — which is exactly what D-BUD4 asks to measure. |
| `max_turns` | **50** | The ROADMAP frames the unknown as 20-50 turns; Pitfall 6 puts degradation onset near 30k tokens. 50 contains both the reliable zone and the degradation zone, so telemetry captures the transition instead of stopping before it. |
| `max_tokens` / `max_wall_clock_s` | **set from calibration** (plan 03-16, D-BUD1) | Multiples pre-registered before calibration runs: **3x** the observed median billed tokens, **4x** the observed median elapsed. Separate multiples because tool-execution time is heavier-tailed than token count. |

**Pitfall 4 — the D-BUD2 hole that must be closed here.** In enumerate mode (`citation=None`), `read_guideline` returns requirement metadata and **records no spans** (`read_guideline.py:45-57`). Under D-BUD2's literal wording an enumerate turn is unproductive, so two enumerate calls plus one already-seen search would trip a DR window of 3 and halt the loop **during the exact RULES-05 mechanism `absence_of_evidence` depends on.** The amendment: a third productivity clause — *"or a requirement_id enumerated for the first time this session."*

**Pitfall 8 — token accounting.** `Sum(prompt_tokens + completion_tokens)` across turns re-counts conversation history every turn. That is the **billed** total, not the unique-token total, and the two diverge by a large factor over 30 turns. Billed is the pre-registered definition: it is real cost and it naturally penalizes history growth, which is the pressure D-BUD5 intends.

Create `src/agents/review/budget.py`. Follow `ledger.py`'s shape exactly: a plain accumulator class, constructor-injected, one instance per run, no module globals, no I/O, no imports from the loop.

**(a) The class.** Configuration is constructor arguments (so a test can set a low ceiling), accumulated state starts at zero:

```python
@dataclass
class BudgetLedger:
    """Every AGENT-03 / AGENT-04 stop condition as CODE, never as a prompt instruction.

    Constructor-injected, never a module global (Security Domain V3, mirroring
    tools/ledger.py:3-5): one instance per agent run. A BudgetLedger shared across runs would
    carry run 1's spend into run 2 and corrupt the 3-run comparison D-GO2 rests on.

    D-BUD5: the budget is PER-RUN, not per-document. A per-document budget would let an agent
    exhaust itself on document 1 and skim the rest -- reproducing the 2/28 ceiling by a different
    route while each document individually looked well-behaved. Tool results count because they
    are the dominant token cost in a retrieval loop; wall-clock includes tool execution because
    the ceiling bounds real elapsed cost, not model-thinking time alone.
    """

    # configuration (frozen values land in 03-GO-NOGO-PREREGISTRATION.md per D-GO5)
    max_tokens: int
    max_wall_clock_s: float
    max_turns: int = 50
    dr_window: int = 3
    breaker_repeat: int = 3
    breaker_same_class: int = 4
    max_continuations: int = 5

    # accumulated
    billed_tokens: int = 0        # Sum(prompt_tokens + completion_tokens) -- Pitfall 8: BILLED, not unique
    cached_tokens: int = 0        # Sum prompt_tokens_details.cached_tokens (COST-01 visibility)
    turns: int = 0
    continuations: int = 0
    usage_missing_turns: int = 0  # turns where usage_present was False -> figures are ESTIMATES
    started_at: float = 0.0
    which_bound: str = ""         # D-BUD4: "" | "diminishing_returns" | "max_continuations"
```

**(b) Accounting entry points:**
- `record_turn(turn: ChatTurn) -> None` — adds `prompt_tokens + completion_tokens` to `billed_tokens`, adds `cached_tokens`, increments `turns`, and increments `usage_missing_turns` when `turn.usage_present is False`. When usage is absent, fall back to a **declared** `len(text)//4` character estimate and mark the turn — never silently add zero, which would disable the ceiling entirely.
- `record_productivity(new_span_ids: int, new_faults: int, new_requirement_ids: int) -> None` — appends one boolean to a rolling productivity window. **A turn is productive iff any of the three is greater than zero** (D-BUD2 plus the Pitfall-4 amendment). Document the third clause inline:

```python
        # D-BUD2 + Pitfall 4: read_guideline's ENUMERATE mode records NO spans
        # (read_guideline.py:45-57), so under D-BUD2's literal wording an enumerate turn is
        # unproductive -- and enumerate,enumerate,known-search would trip a dr_window of 3 during
        # the exact RULES-05 mechanism absence_of_evidence depends on. Hence the third clause.
```
- `record_tool_call(tool: str, args: dict) -> None` — appends a normalized `(tool, canonical_json(args))` key to a call history for the identical-args breaker.
- `record_rejection(reason_code: str, half: str) -> None` — appends `(reason_code, half)` to a rejection history for the same-class breaker; a successful (non-rejected) tool result **resets** the consecutive counter.
- `record_wall_clock(elapsed_s: float)` or an injected clock — wall-clock must be measurable without real sleeping. Take a `clock: Callable[[], float] = time.monotonic` constructor argument so a test injects a fake clock (VALIDATION.md requires `test_wallclock_ceiling` with an injected clock).

**(c) The six stop-condition predicates**, each pure and independently testable:

```python
    def over_ceiling(self) -> bool: ...            # billed_tokens >= max_tokens
    def over_wall_clock(self) -> bool: ...         # clock() - started_at >= max_wall_clock_s
    def over_turns(self) -> bool: ...              # turns >= max_turns
    def in_diminishing_returns(self) -> bool: ...  # last dr_window entries all unproductive
    def breaker_tripped(self) -> str: ...          # "" | "identical_args" | "same_class"
    def may_nudge(self) -> bool: ...               # D-BUD4: not in DR AND continuations < max
```

`breaker_tripped` returns the **reason string**, not a bool, so telemetry and the report can name which condition fired. `in_diminishing_returns` must return `False` until at least `dr_window` turns have been recorded — otherwise a fresh run with an empty window trips instantly.

`may_nudge` is the AGENT-04 gate. When it returns `False`, set `which_bound` to `"diminishing_returns"` if DR is what blocked it, `"max_continuations"` if the cap did. D-BUD4 requires recording which bound ended the nudging: hitting DR means the model was genuinely finished and the floor was correctly permissive; hitting the hard cap means the model was producing just enough novelty to keep being nudged — *"a different and more troubling behavior that Phase 4's fan-out would multiply."*

**(d) `stop_reason() -> str`** returning the harness-owned taxonomy D-TEL5 names, in a fixed precedence order so a run has exactly one reason: `"ceiling"` (tokens or wall-clock) > `"breaker"` > `"max-turns"` > `"diminishing-returns"` > `"completed"`.

No prompt strings, no model interaction, no file I/O in this module.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model behavior to resource consumption | The model drives an unbounded number of turns and tool calls; only code limits it |
| Provider `usage` to the ceiling | The ceiling's input comes from a third party; a missing value must not read as zero |
| Run 1 state to run 2 | The 3-run comparison requires each run's accounting to be isolated |
