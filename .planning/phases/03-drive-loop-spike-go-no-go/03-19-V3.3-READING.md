## Reviewer diagnosis — the wiring bet is spent

v3.3's fix (U1/U2/U3) **worked**: oracle leads now surface live (`oracle_leads_surfaced` ≈ 23
per run; the U1 dict-tracker fires). Yet the agentic loop on `databricks-meta-llama-3-3-70b-instruct`
still will not **convert** surfaced leads into the C-01/B-08 findings, and it emits **zero**
absence-of-evidence deficiencies across all three runs. This is no longer a plumbing/wiring
problem — it is a **general reasoning weakness**: the lead → `get_section` → `read_guideline` →
`emit_finding` conversion, and "a required item is ABSENT" reasoning, do not hold on the local
model. The pre-registered decision point (recorded in `03-19-V3-READING.md`) is now triggered.

## Architecture decision (reviewer's call, user-approved)

The three pre-registered options were α (code-inject oracle leads at turn 1), β (deterministic
pipeline owns recall; agentic loop verifies/challenges only), γ (escalate the orchestrator to
a stronger model).

- **β is adopted.** Recall moves to a **general** deterministic layer — FDA/ICH
  rulebook-requirement enumeration (for absence: enumerate required items, check presence) plus
  structural consistency (numeric cross-reference, spec exceedance). The agentic loop is retained
  only for **verify/challenge**. Absence detection is *inherently* a rulebook-enumeration problem
  (you cannot read what is not present), so this is the correct general mechanism, not a
  corpus-specific check.
- **α folds in as a sub-step** of β (deliver the general oracle leads by code, not prompt).
- **γ is EXCLUDED — permanently.** Hard on-premise / privacy constraint: only self-hosted
  open-weights models (Llama 3.3 70B, Qwen MoE on the company's Databricks) are permitted; no
  external LLM API (Claude/GPT). Recall therefore cannot be bought with a stronger hosted model.
  (A survey for **one** additional self-hosted open-weights *reasoning* model — for the retained
  verify/hard-reasoning role only — is in progress; it does not reopen γ.)

## HARD guardrail — do not chase this metric

Folders are unique; the eval corpus is a **proxy**. β's recall layer must stay
rulebook + structure **general** — the same FDA/ICH rulebook applied to any submission. If any
check is ever tuned to recover a specific item on *this* corpus, that is overfitting and we stop.
The goal is general deficiency detection on arbitrary submissions, never a number on mvr1381.
