<objective>
Wire every stop condition into the loop and build the anti-premature-stop floor.

**AGENT-04 is the recall requirement.** The measured failure is 2/28 — an agent that stops after finding a few obvious faults reproduces exactly that ceiling, and **no ceiling-only budget can prevent it.** So the budget is bidirectional: when the model emits no tool call but is still well under budget and not in diminishing returns, the loop **does not accept the stop**. It injects a continuation nudge and runs another turn. The model's self-assessment of "done" is **not** a termination condition. Verbatim precedent: Claude Code `query.ts:1338` `token_budget_continuation` + `utils/tokenBudget.ts:72` — *"Stopped at {pct}% of token target. Keep working — do not summarize."*

**Enforced in code, never as a prompt instruction.** Plan 03-13 already asserts `SYSTEM_PROMPT` contains no stop language. This plan puts the conditions where the model cannot address them.

**D-BUD6 is how SC3 gets proven without flakiness.** A synthetic forced-runaway driver — never emits a stop, always requests more evidence — runs against the **real loop and real `src/tools` functions**: deterministic, offline, CI-runnable under D-RB6, zero LLM spend, exercising exactly what SC3 claims (ceiling trips, grounded partial returned, no crash, no overspend). *A code gate deserves a test that cannot be flaky for model reasons.*

**D-LOOP5 completes the picture.** A `ToolRejected` goes back to the model **as the tool's result** — the typed, self-correcting message it reads and retries from — and it **consumes a turn** like any other. Counting the turn keeps the budget honest (repair attempts are real work and must show in the token curve) and lets the breaker see the repeated-identical-failing-call pattern.

Purpose: AGENT-03 and AGENT-04 are satisfied here or not at all.
Output: the stop wiring, the floor, and eleven tests including the runaway driver.
</objective>

**The AGENT-04 floor, from RESEARCH.md Pattern 5:**

```python
if not turn.tool_calls:
    if budget.may_nudge():
        telemetry.continuation(tokens_at_stop=budget.billed_tokens,
                               findings_before=len(findings))
        messages.append({"role": "user", "content": NUDGE})   # NUDGE is a module constant
        budget.continuations += 1; budget.turns += 1
        continue
    return ReviewResult(findings, stop_reason="completed")
```

The Claude Code original (`utils/tokenBudget.ts:59`): continue while under 90% of budget, but stop early when `continuationCount >= 3` **and** successive deltas are `< 500` tokens; on continue, inject a nudge message rather than silently looping.

**`BudgetLedger`'s surface** (plan 03-07): `over_ceiling()`, `over_wall_clock()`, `over_turns()`, `in_diminishing_returns()`, `breaker_tripped() -> str`, `may_nudge() -> bool`, `stop_reason() -> str`, `which_bound`, plus recorders `record_turn`, `record_productivity`, `record_tool_call`, `record_rejection`. Frozen defaults: `max_turns=50`, `dr_window=3`, `breaker_repeat=3`, `breaker_same_class=4`, `max_continuations=5`.

**`stop_reason` precedence** (fixed, so a run reports exactly one): `ceiling` > `breaker` > `max-turns` > `diminishing-returns` > `completed`.

**D-BUD2's productivity definition, with the Pitfall-4 amendment**: a turn is productive iff it surfaced span-IDs not previously issued this session, **or** landed a finding through the emit gate, **or** enumerated a `requirement_id` for the first time this session. Re-reading an already-retrieved span returns the COST-04 *"still current"* stub and counts as nothing — so an agent circling over familiar evidence trips diminishing returns, while one legitimately gathering before it emits does not.

**D-TEL5's continuation record**: `continuation_count`; `tokens_at_each_attempted_stop` (was it quitting at 20% of budget?); `findings_before_vs_after_each_nudge` (**the decisive number**); which stop reason ended the run; `continuation_count` reported **against the permitted max**; and **which bound** ended the nudging.

**D-TEL5's pre-registered readings** — build the telemetry so each is answerable:
- Nudges yield new grounded findings ⇒ the mechanism **works and is load-bearing for recall**.
- Nudges yield **zero** new findings across all runs ⇒ the model was genuinely done, the nudge burns budget, reconsider AGENT-04 in Phase 4.
- `continuation_count = 0` across all runs ⇒ the model never tried to stop early, **the floor was never exercised and is UNPROVEN, not validated.**

**The D-BUD6 driver shape** (`ForcedRunaway` from plan 03-05) varies its query per call so the identical-args breaker does NOT trip — the **token ceiling** must be what ends the run, or the test proves the wrong gate. Set `max_turns` deliberately high for the same reason.
