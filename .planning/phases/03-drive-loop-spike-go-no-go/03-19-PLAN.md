<objective>
Turn nine committed artifacts into an evidence package the senior reviewer can rule on — and stop there.

**The framing that produced this whole phase:** *"An un-diagnosed NO-GO wastes the spike."* A gate result without a diagnosis cannot tell you whether to swap the model, fix the loop, or abandon the approach. The five telemetry signals are as much the deliverable as the number.

**And the boundary this plan must not cross.** D-GO5: *"The GO/NO-GO call is the senior reviewer's, made against the committed pre-registration. The executor reports numbers and telemetry; it does not declare the verdict."* On a clean NO-GO, *"Phases 4-6 do not auto-proceed"* — the next move is a reviewer decision at the gate, not a planned branch.

So this plan produces two documents and one checkpoint. It evaluates each pre-registered criterion against the measured evidence and says what the evidence shows for that criterion. It does not aggregate them into a verdict.

Output: the cross-run comparison, the diagnostic phase report, and the reviewer sign-off.
</objective>

**Artifact naming.** Every run artifact this plan reads follows plan 03-15's contract `{prefix}{run_index}` with `--run-prefix` defaulting to `agent-run`: the three scored runs are `agent-run{N}.json`, `agent-run{N}.jsonl` and `agent-run{N}-summary.json`. The unscored executions carry different prefixes by construction — `smoke-`, `calibration-run`, `probe-`, `lowceiling-` — and must never be read into the comparison or the median. Every path in this plan names `agent-run{1,2,3}` explicitly for exactly that reason; do not glob.

**Scoring uses frozen harness functions only.** `capture.load_captured` then `metrics.recall_by_family(report, eval_set, "mvr1381")` then `statistics.median`. `metrics.recall_by_family` (`metrics.py:230-234`) is the frozen implementation; a spike-local scorer *is* a harness change under D-GO1(iii).

**The gate criteria, from the committed pre-registration:**
- **D-GO1(a)** at least one currently-zero family (`absence_of_evidence`, `derivation_plausibility`, `regulatory_framing`) moves off 0.0 with at least one **grounded** true positive, **AND (b)** the baseline `found_set {C-01, C-02}` is not lost.
- **(i)** The derived arithmetic: (a)+(b) jointly imply overall recall strictly above baseline (tp >= 3 > 2).
- **(ii)** Precision is REPORTED, never gated; **fp > 125 ⇒ GO-WITH-CONCERNS**.
- **(iii)** The report **must state specifically whether absence moved** — a pass while `absence_of_evidence` stays 0/11 means the mechanism built for it did not work and Phase 4 needs to know.
- **D-GO2(iii)** the headline is the **MEDIAN, never the max**; the union may be reported as a separate diagnostic labelled *"what the loop can find across 3 runs"*.
- **D-GO2(iv)** if the 3 runs disagree on **which** families unlock, that is **GO-WITH-CONCERNS, not a clean GO** — the loop is unreliable in a way Phase 4's fan-out amplifies.
- **D-GO4(a)** if the gate FAILS but every structurally-reachable item was found, that is a **NO-GO on single-agent SCOPE, not on the architecture** — Phase 4's reference graph is the named next step. **(b)** if the gate PASSES, the headline stays the **frozen whole-set figure**, never the reachable-subset figure.

**The three reachability buckets** (`03-REACHABILITY-CLASSIFICATION.md`): matcher-unreachable (5 `mvr1381` items, permanent false negatives for any system; overall ceiling 23/28 = 0.821), single-agent-scope-unreachable, reachable.

**D-TEL3's matrix — opposite diagnoses, never summed:**
- `half=submission` + `not_byte_exact` ⇒ **SPAN INVENTION** — grounding-discipline failure; the gate did its job, the loop is unreliable.
- `half=rule` + `not_retrieved_this_session` ⇒ **NEVER CALLED `read_guideline`** — loop-behavior failure; the enumerate-to-fetch-to-emit chain is not being followed.
These imply **different NO-GO remedies** (different model vs fix the loop/prompt), so the diagnosis section **must name which pattern dominated**.

**D-TEL5's three pre-registered continuation readings:**
- Nudges yield new grounded findings ⇒ the mechanism **works and is load-bearing for recall**.
- Nudges yield **zero** new findings across all runs ⇒ the model was genuinely done, the nudge burns budget, reconsider AGENT-04 in Phase 4.
- `continuation_count = 0` across all runs ⇒ **the floor was never exercised and is UNPROVEN, not validated** — say so explicitly rather than claiming the mechanism works.

**D-ORC2's conversion readings:** a **low re-open rate** means the agent is ignoring deterministic leads — recall lost to demotion, report it plainly. A **high re-open-but-low-emit rate** means the oracles are surfacing noise.

**A reporting artifact to disclose rather than present as independent:** `_verifier_metrics` (`metrics.py:159-193`) keeps findings whose `tier != ADVISORY`. On the agent path *all* findings are `CORROBORATED` (`emit_finding.py:114`), so the `verifier` metric degenerates to the same numbers as `end_to_end`. Say so.
