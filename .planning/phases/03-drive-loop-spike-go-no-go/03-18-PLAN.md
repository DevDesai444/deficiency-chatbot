- `databricks-meta-llama-3-3-70b-instruct` — the recall gate, baseline-matched
- `databricks-qwen35-122b-a10b` and `databricks-qwen3-next-80b-a3b-instruct` — fidelity probe only

**D-GO3(ii)'s pre-registered Qwen bar**, both clauses required:
- (a) valid tool calls with schema-conformant args at **>=95% of turns**. `structured.py` coercion may fix type slips (e.g. the known `top_k`-as-string), but a call that **cannot** be repaired counts as a failure.
- (b) **>=1 finding that passes the emit gate**, proving it can drive the full enumerate-to-fetch-to-emit chain, not just format a call.

**D-TEL4 applies the same >=95% post-repair bar to Llama**, with pre-repair and post-repair recorded **separately**: *"A loop at 95% post-repair but 40% pre-repair is a loop the fallback is carrying — that must be visible, not hidden behind a passing number."* Below the floor ⇒ **GO-WITH-CONCERNS, never NO-GO.**

**D-GO2(i):** a failed/errored run is a **FAILING run, not a re-roll**. Sole exception: an infrastructure fault wholly outside the loop (endpoint 5xx / auth expiry with **zero tool calls made**); the re-run and its reason are recorded.

**D-GO2(ii):** all 3 runs fixed and identical in configuration before the first executes — model, budgets, prompt, corpus, harness/matcher/baseline; seeds/temperature at 0. **Any change voids the set and all 3 re-run.**

**Pitfall 3's reporting requirement:** record a **turn-indexed** fidelity metric, not just a run aggregate, plus the turn index at which the first malformed call appears — so degradation-with-depth is visible rather than averaged away.

**Re-scoring** (`evals/capture.py:16-18`): `python -m evals.run score --captured <path>` reproduces a run's numbers with no LLM call.
