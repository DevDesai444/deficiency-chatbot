<objective>
Extend the emit_finding grounding gate with an absence variant and add the CoverageAbsenceAnchor
schema — the single Phase-2↔Phase-4 integration seam (D-GATE1/D-GATE2). This is the grounding
substrate Plan 03's deterministic absence pass emits through.

Purpose: An absence finding cannot carry a single submission text span (a never-mentioned or
whole-section absence has none). D-GATE1 keeps the RULE half byte-exact and replaces the submission
half with a typed CoverageAbsenceAnchor that stores the enumerate inputs + sub-threshold retrieval
hits, so the Phase-7 verifier RE-RUNS the negative (D-GATE2) — the negative is independently
reproducible, not a recorded assertion.

Output: CoverageAbsenceAnchor model; Fault.absence_anchor field; emit_absence_finding gate;
new reason codes; tests proving byte-exact rule half, re-derivable anchor, and rejection of a
fabricated CORPUS-claim span.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| absence candidate → emit gate | an absence finding could carry an ungrounded rule span or a fabricated narrative-claim span |
| CoverageAbsenceAnchor → Phase-7 verifier | the verifier trusts the anchor to re-run the negative; a non-re-derivable snapshot would defeat verification |

Offline, deterministic, in-process. No network endpoint, no untrusted runtime input, no auth surface —
web-app threats do not apply.
