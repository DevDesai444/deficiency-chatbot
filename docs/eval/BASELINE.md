# Phase 0 baseline — the starting line every later phase must beat

**Source measurement:** [`docs/eval/MEASUREMENT.md`](./MEASUREMENT.md) — run 3 on `mvr1381`
(Estradiol USP related-compounds HPLC method verification, `data/32s43-validation-related-compounds-method.pdf`),
Qwen3-Next 80B · A3B (MoE), measured 2026-07-29 on branch `CLI_for_folders`.

**Committed baseline artifact:** [`src/evals/baseline/recall_by_family.json`](../../src/evals/baseline/recall_by_family.json),
generated by scoring the committed golden fixture (`src/evals/dataset/golden/mvr1381_run3.json`,
run 3's findings transcribed verbatim) with `evals.metrics.compute_metrics`. Every number below is
reproducible, deterministically, with no LLM call:

```
PYTHONPATH=src uv run python -m evals.run score --captured src/evals/dataset/golden/mvr1381_run3.json
```

## Headline

| Metric | Value |
|---|---|
| **Recall vs. the 28-item ground truth** | **7.1 % (2 / 28)** |
| Precision — human-reviewed, run 3 (MEASUREMENT.md) | 16 % (5 of 31 findings labeled TRUE_POSITIVE) |
| Precision — this harness's deterministic anchor-matcher | 7.4 % (2 distinct GT ids matched / 27 findings scored TP-or-FP) |
| anchor_rate (fraction of findings whose evidence verbatim-resolves in the source PDF, checker note W1) | 58.1 % |
| retrieval_recall_at_k (Phase-0 section/table-overlap proxy) | 57.1 % |

The two precision numbers are both real and measure different things, not a discrepancy to
resolve: MEASUREMENT.md's 16 % is a human reviewer's per-*finding* TRUE_POSITIVE/FALSE_POSITIVE/WEAK
label rate (5 of 31 findings). This harness's 7.4 % is `tp / (tp + fp)` where `tp` is the count of
*distinct* matched ground-truth ids — several findings restating the same real deficiency collapse
to one TP for recall (see `evals.match.score`'s many-to-one collapse), so each is still its own
finding for the human label rate but only one distinct hit for the gate. Both agree on the number
that actually matters for the gate: **2 distinct real deficiencies found, out of 28.**

## Recall by failure family

| Failure family | Recall | TP | FN |
|---|---|---|---|
| absence_of_evidence | 0.000 | 0 | 11 |
| derivation_plausibility | 0.000 | 0 | 5 |
| cross_reference_integrity | **0.286** | 2 | 5 |
| regulatory_framing | 0.000 | 0 | 5 |

Both hits land in `cross_reference_integrity` — the "compare a number against a limit / against
another cell" family, precisely the oracle-shaped task (MEASUREMENT.md's "What this says about the
architecture"). The other three families sit at 0 % recall; closing them needs reasoning the
pipeline has no mechanism for yet (assertion-vs-evidence sweeps, derivation plausibility, document-
control review — see MEASUREMENT.md's "Recommended next steps").

## The two found deficiencies (the protected found-set)

- **C-01** — Table 20's "Maximum" theoretical-plates cell reads 11477, but the true maximum across
  the tabulated rows (including the In-house Equivalency Study row) is 12601.
- **C-02** — An unspecified impurity of 0.15 % is reported as meeting the NMT 0.10 % limit in the
  equivalency study, and the section still concludes equivalency.

`["C-01", "C-02"]` is exactly `found_set` in `recall_by_family.json`, and exactly the two
`tp_required` anchors in the ground-truth eval set (`EvalSet.tp_required()`) — the baseline the
zero-true-positives-lost gate protects.

## The rule this baseline enforces

**Every later phase must move recall-by-family UP without losing a true positive** — enforced in
code, not a prompt or a convention (MEASUREMENT.md: "every reliable improvement this session came
from a code gate, not a prompt"), by:

```
python -m evals.run gate
```

which fails loudly (non-zero exit) and names the lost id(s) the moment C-01, C-02, or any later id
added to the found-set stops being found in a new run. See `src/evals/gate.py` and
`tests/evals/test_gate.py` for the implementation and the doctored-report regression test that
pins this behavior.
